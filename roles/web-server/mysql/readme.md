# Роль MySQL (prod)

Ставит **MySQL 8.4 LTS** из официального APT-репозитория Oracle (Ubuntu 24.04
в своём apt отдаёт только 8.0; единая с dev-докером версия — 8.4 LTS, поддержка до 2032).

## Аутентификация

- Используется `caching_sha2_password` (в MySQL 8.4 `mysql_native_password` отключён,
  переменная `default_authentication_plugin` удалена — с ней сервер не стартует).
- PHP 8.4 (mysqlnd) и современный HeidiSQL полностью поддерживают `caching_sha2_password`.
- `root@localhost` ходит через unix-socket → полная аутентификация безопасна без TLS.

## TLS соединений — осознанно НЕ включаем

Решение: `ssl-*` / `require_secure_transport` в `mysqld.cnf.j2` не добавляем.
Обоснование под топологию проекта:

- `bind-address = 127.0.0.1` — MySQL наружу не торчит.
- Приложение и `root@localhost` ходят через **unix-socket**: это файл с правами
  доступа, в сеть не уходит, MySQL для сокета TLS не применяет — шифровать нечего.
- Удалённый админ (HeidiSQL) — через **SSH-туннель** на `127.0.0.1:3306`.
  Единственный сегмент, покидающий хост, уже шифруется SSH; MySQL TLS поверх —
  избыточное двойное шифрование.
- Loopback на Linux снифается только с root/CAP_NET_RAW. Атакующему с root TLS
  не мешает (пароль БД лежит в конфиге приложения, datadir читается напрямую) —
  TLS-to-localhost после компрометации хоста даёт нулевую доп. защиту.
- `caching_sha2_password` через unix-socket полностью безопасен без TLS
  (см. раздел «Аутентификация»).

⚠️ Особенно НЕ ставить `require_secure_transport=ON` / per-user `REQUIRE SSL`:
для неуправляемого годами сервера это мина тихого отказа — при подключении без
TLS (смена параметров/способа) MySQL молча отвергнет соединение → сайт в 500,
обнаружится по звонку.

Единственная легитимная причина пересмотреть — внешний аудит (PCI/GDPR),
механически требующий «encryption in transit везде». Это бумажное требование,
не безопасностное. Усиление по делу — убедиться, что DSN Yii2 использует
unix-socket (`unix_socket=/var/run/mysqld/mysqld.sock`), а не TCP.

## Особенности установки

- Пароль root и режим строгого шифрования задаются неинтерактивно через `debconf`
  (`install.yml`), поэтому установщик Oracle не спрашивает их в диалоге.
- Бутстрап root идемпотентен: подключение всегда через unix-socket с паролем из Vault.

## Не протестировано на живом сервере

Удалённого сервера пока нет. Переход на Oracle APT-репозиторий и debconf-preseed
требует проверки на чистом тестовом сервере (особенно первый прогон на свежей машине).
